# KING Music 0.5.16 — инструкция по выпуску

**Статус:** исходники подготовлены, JAR должен быть собран и подписан на Windows пользователя. Исправление «Моей волны» ещё не протестировано с аккаунтом Яндекс Музыки.

1. Сделайте резервную копию `king-music-main` и текущего `official/manifest.txt` и `official/manifest.sig`.
2. В PowerShell в папке проекта запустите `python .\build.py` (JDK 25 и профиль Modrinth Minecraft 26.2 обязательны).
3. Проверьте `java -cp .\tools ReleaseSigner verify .\official\manifest.txt .\official\manifest.sig` (ключи в `%USERPROFILE%\.kingmusic`; **никому не отправлять приватный ключ**).
4. Откройте `official/manifest.txt`: старые хеши модов 0.5.15, Lyrics 0.1.5, Together 0.2.1, Visualizer 0.1.1 должны сохраниться; добавится новый `King-Music-0.5.16-Fabric-26.2.jar`.
5. Убедитесь, что SHA-256 нового файла совпадает со строкой его имени в манифесте.
6. Сначала перенесите в GitHub только обновлённые исходники и оба файла `official/manifest.*`; дождитесь появления изменений в ветке `main`. Лишь затем создавайте GitHub Release с тегом `v0.5.16` и загружайте только новый основной JAR.
7. Протестируйте новый JAR на отдельном профиле, особенно авторизацию и ручное переключение «Моей волны». Только после этого загружайте на CurseForge.

**Важно:** `build.py` пересобирает аддоны, но в этом релизе они НЕ переиздаются. Манифест намеренно сохраняет контрольные суммы *ранее опубликованных* аддонов. Не загружайте заново пересобранные аддоны под старыми номерами версий. Если понадобится обновить аддон, ему требуется новый номер версии и отдельный релиз.

**Ограничение текущего обновлятора:** старая версия 0.5.15 выбирает первую подходящую запись манифеста через HashMap; при двух версиях в подписанном манифесте уведомление о 0.5.16 на старых клиентах может появляться нестабильно. Новая версия 0.5.16 выбирает максимальную доступную версию. Для исправления обновления старых клиентов понадобился бы отдельный совместимый механизм.
