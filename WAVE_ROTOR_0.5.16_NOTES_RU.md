# KING Music 0.5.16 — Rotor feedback / queue hotfix

Из диагностики 2026-11-17: сервер возвращал по пять треков, большинство повторялось, а мод передавал только один ID в `queue` и не сообщал `skip` / `trackFinished`.

Изменения:
- `queue` теперь передаёт список последних треков (повторяющиеся параметры `queue=...`, максимум 24) плюс курсор.
- Читается `batchId` из ответа `/rotor/station/.../tracks` и сопоставляется с треком.
- `radioStarted`, `trackStarted`, `trackFinished`, `skip` отправляются как реальные события пользователя; отдельный виртуальный поток не тормозит звук.
- Длительность в `totalPlayedSeconds` берётся из фактического проигрывания, а не подделывается.
- Лог фиксирует количество ID в очереди, присутствие `batchId`, тип обратной связи и HTTP-статус, не пишет токены.
- Версия остаётся `0.5.16`; `BuildTrust` и ключ подписи не меняются. Дополнения не меняются.

## Сборка и обновление существующего релиза

1. Распаковать архив, открыть PowerShell 7 в папке `king-music-main`.
2. Выполнить `Set-ExecutionPolicy -Scope Process Bypass -Force`.
3. Выполнить `.\\PUBLISH_0.5.16_WAVE.ps1`.
4. Скрипт сам запускает тесты, строит JAR (нужен JDK 25), подписывает и проверяет манифест, переносит изменения в `C:\Users\User\Desktop\king-music-release`, делает push и заменяет JAR в **том же** GitHub Release.

ВНИМАНИЕ: Это тестовая реализация на основе публично описанного неофициального протокола Rotor. Нет возможности проверить реальные HTTP-ответы от аккаунта пользователя в этой среде. Если обратная связь возвращает HTTP 400/404, пришлите `config/king-music-wave-debug.log`.
